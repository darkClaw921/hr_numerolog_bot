# Бот для нумерологических расчётов

Telegram-бот на aiogram для нумерологических расчётов по дате рождения: матрица
Пифагора, коэффициенты секторов, Число Судьбы, интерпретации, комбинации, личный
кабинет и полный отчёт. Данные хранятся в SQLite (общая БД, готова для будущего
бота совместимости).

## Установка

1. Установите зависимости:
```bash
uv sync
```

2. Создайте файл `.env` в корне проекта (см. `.env.example`):
```
BOT_TOKEN=your_telegram_bot_token_here
DATABASE_URL=sqlite+aiosqlite:///./numerology.db
ADMIN_USER_IDS=123456789          # ваш Telegram ID (для команды /grant)
PREMIUM_USER_IDS=                  # опционально: ID с премиумом без оплаты
SUBSCRIPTION_PRICE_RUB=299
```

Токен получают у [@BotFather](https://t.me/BotFather) (`/newbot`). БД-файл
создаётся автоматически при первом запуске.

## Запуск

```bash
uv run main.py
```

## Использование

1. Отправьте боту `/start`.
2. Отправьте дату рождения в формате `DD.MM.YYYY` (например, `18.08.1984`).
3. Нажимайте кнопки для интерпретаций секторов и качеств.
4. Сохраняйте людей, смотрите историю, управляйте подпиской и приглашайте друзей в личном
   кабинете (`/menu`). Из любого раздела есть кнопка «Назад» — к результатам или в профиль человека.

## Команды

В кнопке «Меню» Telegram — только `/start` и `/menu`; остальные команды работают, но не показываются.

- `/start` — начать работу (`/start ref_<id>` — вход по реферальной ссылке)
- `/menu` (или `/cabinet`) — личный кабинет: люди, история поисков, подписка, бонус
- `/help` — справка
- `/subscribe` — подписка: статус или ссылка на оплату
- `/unsubscribe` — отключить автопродление (то же — кнопкой в кабинете → «Подписка»)
- `/admin` — панель админа: переключение режима «🛠 Админ» / «👤 Пользователь без подписки» /
  «💎 Пользователь с подпиской», чтобы пройти все экраны глазами клиента (только для `ADMIN_USER_IDS`,
  у админов команда есть в меню). В режиме пользователя премиум имитируется (реальная подписка и
  `PREMIUM_USER_IDS` игнорируются, отмена реальную подписку не трогает), `/grant` и `/payments`
  недоступны. Режим хранится в памяти и сбрасывается в «Админ» при перезапуске бота.
- `/grant <telegram_id> [дней]` — выдать премиум (только для админов)
- `/payments <telegram_id>` — журнал платежей пользователя (только для админов)
- `/cancel` — отменить добавление человека

## Платные функции (подписка 299 ₽/мес)

🔒 Полный общий отчёт (текст + файл `.md`), 🧩 комбинации секторов и коэффициенты
Быт/Темперамент/Семья/Стабильность. Бесплатны: секторы 1-9, Целеустремлённость,
Число Судьбы. «Трансформация» скрыта из интерфейса до обновления текстов.

Оплата — рекуррентная подписка Prodamus. Премиум включается **только** по
уведомлению Prodamus (webhook); возврат пользователя на страницу успеха ничего не
активирует. Помимо оплаты премиум можно выдать вручную (`/grant`) или через
`PREMIUM_USER_IDS`.

### Реферальная программа

Кабинет → «🎁 Бонус» выдаёт ссылку `t.me/<bot>?start=ref_<bot_users.id>`. Пришедший по
ней новый пользователь (без подписки и платежей) привязывается к пригласившему
(таблица `referrals`). При **первой** успешной оплате приглашённого пригласившему
начисляется `REFERRAL_BONUS_DAYS` (по умолчанию 10) дней премиума — один раз за друга.
Если у пригласившего идёт автопродление, дата следующего списания сдвигается в Prodamus
(`setSubscriptionPaymentDate`, по телефону клиента) в фоне, после ответа на вебхук. Если
перенос не удался, дни копятся в `subscriptions.referral_bonus_pending_days`, и перенос
повторяется при следующем успешном списании (ошибка пишется в лог). Бонус не начисляется
за уведомление с нулевой суммой (пробный период).

## Платежи Prodamus

Все переменные окружения описаны в `.env.example`. Ключевое:

- `PAYMENTS_ENABLED=true` включает приём оплат и поднимает HTTP-сервер вебхука
  рядом с long polling (порт `PRODAMUS_WEBHOOK_PORT`, путь `PRODAMUS_WEBHOOK_PATH`).
  При `false` бот работает как раньше и сервер не поднимается.
- `PRODAMUS_SECRET_KEY` хранится **только** в `.env` — не в коде и не в логах.
- `PRODAMUS_SUBSCRIPTION_ID` — ID клубной подписки, созданной в ЛК Prodamus.
- `PUBLIC_BASE_URL` — публичный HTTPS-адрес; из него собирается `urlNotification`.
  Наружу путь вебхука проксирует reverse proxy (заголовок `Sign` должен доходить
  до бота без изменений).

При `PAYMENTS_ENABLED=true` бот падает на старте, если не заданы
`PRODAMUS_SECRET_KEY`, `PRODAMUS_SUBSCRIPTION_ID`, `PUBLIC_BASE_URL` (https) или
`BOT_USERNAME` — так исключены молча битые ссылки на оплату.

Проверить приём уведомлений локально:

```bash
uv run python scripts/send_test_webhook.py --order-id <order_id из payment_intents>
uv run python scripts/send_test_webhook.py --order-id <тот же> --break-signature  # ожидаем 400
```

Схема БД доводится автоматически при старте (`src/db/migrations.py`): alembic в
проекте нет, новые колонки добавляются идемпотентно и только nullable — БД
остаётся совместимой с будущим ботом совместимости.

## Что рассчитывает бот

1–4. Дополнительные числа (по алгоритму матрицы).
5. Матрица (секторы 1-9): Характер, Энергия, Интерес, Здоровье, Логика,
   Деньги/Труд, Удача, Долг, Память.
6. Коэффициенты секторов: Темперамент (3/5/7), Быт (4/5/6), Цель (1/4/7), Семья (2/5/8).
7. Число Судьбы (профессиональный вектор).
